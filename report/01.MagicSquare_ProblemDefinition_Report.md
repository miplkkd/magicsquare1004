# MagicSquare_1004 — Problem Definition Report

**작성일:** 2026-06-04  
**프로젝트:** MagicSquare_1004  
**단계:** STEP 1 (Mom Test) + 세션 3 (주제 선정)

---

## 1. Executive Summary

4×4 부분 마방진(빈칸 2개, 1~16, 합 34)을 다루는 학습자는 행·열·대각선 등 **여러 조건을 동시에 추적**하다 **하나를 놓치면** 틀린 답을 오래 붙잡고 시간을 낭비한다. Mom Test 인터뷰에서 **20분 낭비**와 **대각선 검증 누락**이 과거 사실로 확인되었다.

본 프로젝트의 주제는 솔루션(앱·GUI·Solver) 선정이 아니라, **다중 조건 검증 누락으로 인한 늦은 오류 발견** 문제를 줄이는 것이다.

---

## 2. 도메인 정의

| 항목 | 정의 |
|------|------|
| 격자 | 4×4 |
| 숫자 | 1~16 (중복 없음) |
| 빈칸 | 0, 정확히 2개 |
| 목표 합 | 34 |
| 검증 대상 (10선) | 행 4 + 열 4 + 대각선 2 |

**Magic Square:** 모든 행·열·대각선의 합이 34인 4×4 숫자 배열.

**과제:** 두 빈칸 위치를 찾고 1~16 숫자를 배치하여 완성한다.

---

## 3. 페르소나

4×4 격자, 빈칸 2개(0), 1~16, 합 34를 맞추는 **학습자**.

- 수학/프로그래밍 과제 맥락에서 손으로 풀거나 코드로 구현·검증함
- 행·열·대각선 조건을 동시에 추적해야 함

---

## 4. Mom Test 인터뷰

### 4.1 인터뷰 기록

**질문 1:** 마지막으로 4×4 부분 마방진을 손으로 풀거나 코드로 다루려고 한 게 언제였어? 그때 뭐 하려다가 그걸 하게 됐는지?

**답변:**

> 지난주 OO 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데 대각선 하나를 빼먹어서 20분 날렸다

**질문 2 (미응답):** 20분 날린 그 과정에서, 대각선 하나를 빼먹었다는 걸 언제 처음 알았어? 그 순간까지 뭐 하고 있었는지?

### 4.2 Mom Test 증거 (인용 3줄)

1. "지난주 OO 과제에서"
2. "빈칸 2개 넣고 행·열·대각선 합 맞췄는데"
3. "대각선 하나를 빼먹어서 20분 날렸다"

### 4.3 분석

| 구분 | 내용 |
|------|------|
| **불편** | 여러 조건(행·열·대각선) 동시 추적 중 하나 누락 |
| **비용** | 20분 낭비 |
| **판정** | 대각선 하나 빼먹음 → 답이 틀림 |
| **재현** | 지난주 OO 과제에서 실제 발생 |

---

## 5. 문제 정의

### 5.1 표면 문제 (잘못된 정의 — 증거로 사용 불가)

> "대각선까지 자동 검증해 주는 **마방진 체커 프로그램**을 만든다."

기타 표면 문제 예시:

- "대각선까지 자동으로 검증해 주는 마방진 체커 앱이 있으면 좋겠어."
- "행·열·대각선을 한 번에 보여 주는 UI가 필요해."
- "TDD로 테스트 케이스를 먼저 짜면 실수 안 할 것 같아."

### 5.2 진짜 문제 (한 문장)

> 행·열·대각선처럼 여러 조건을 맞추다 하나를 놓치면, 틀린 답을 오래 붙잡고 있다가 뒤늦게 **20분** 같은 시간을 날린다.

---

## 6. 주제 선정 (세션 3)

### 6.1 주제 한 문장

> **4×4 부분 마방진에서 행·열·대각선(합 34)을 빠짐없이 검증하지 못해, 틀린 배치를 늦게 알게 되는 문제를 줄인다.**

### 6.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | 4×4 부분 마방진(빈칸 2개, 1~16, 합 34)을 풀고 **맞는지 확인**하는 학습자 |
| **Goal** | 행·열·대각선 중 **하나라도** 틀리거나 빠뜨리면 **즉시** 알 수 있다. "맞다"고 착각해 20분 붙잡는 상황을 줄인다 |
| **Input** | 4×4 격자 (숫자 1~16 + 빈칸 0 최대 2개) |
| **Output** | **통과/실패** 판정 + **어느 조건**이 깨졌는지 (예: `대각선 ↘ 합 32 ≠ 34`) |

### 6.3 성공 기준 3개

| # | 성공 기준 | Mom Test 증거 연결 |
|---|-----------|-------------------|
| 1 | **10개 조건**(행 4 + 열 4 + 대각선 2)을 **한 번에** 검사. 대각선 1개만 빼도 **실패** | "대각선 하나를 빼먹어" — 확인 누락 재발 방지 |
| 2 | 행·열만 맞고 대각선이 틀린 배치는 **"맞음"으로 통과하지 않음** | "20분 날렸다" — 늦은 판정 대신 조기 판정 |
| 3 | 실패 시 **어떤 줄/대각선**이 깨졌는지 출력 | "지난주 OO 과제" — 재확인 시간·비용 절감 |

### 6.4 실패 조건 (문제인식)

1. 대각선 ↘ 또는 ↙ 합 ≠ 34
2. 행 또는 열 합 ≠ 34
3. 0(빈칸)이 2개가 아님
4. 1~16 중 중복 또는 범위 밖 숫자
5. 행·열만 맞고 대각선이 틀린 배치를 "완성"으로 판단

## 7. 범위 — 하지 않을 것 (표면 문제)

| 제외 항목 | 이유 |
|-----------|------|
| 마방진 **체커 앱·GUI·뷰어** 전체 | 솔루션 선행. 주제는 검증 **규칙** |
| 빈칸 **자동 채우기 Solver** | Pain은 "풀기"가 아니라 "틀린 줄 모르고 20분" |
| **TDD 방법론** 도입·설교 | 솔루션 이름. Test Loop는 검증 규칙 테스트용만 |
| **GridUI** 시각화 | Boundary는 다음 세션 |
| 기능 확장 (공유, 랭킹 등) | Mom Test ❌ 패턴 |

## 11. 결론

MagicSquare_1004의 문제 정의는 **"마방진 체커를 만든다"** 가 아니라, **"10개 조건(행·열·대각선) 검증 누락으로 20분을 날리는 패턴을 줄인다"** 에 기반한다.  
세션 3에서는 Rule · Command · (Skill) · Test Loop 계층으로 **검증(Validation)** 을 우선 구현한다.
